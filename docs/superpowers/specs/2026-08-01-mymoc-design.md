# MyMOC — плагин Obsidian для оглавлений папок

Дата: 2026-08-01

## Задача

Поддерживать в актуальном состоянии MOC-файлы (Map of Content) — заметки со списком
содержимого своей папки. Замена Zoottelkeeper и Waypoint, у которых два неустранимых недостатка:

1. Фильтры включения/исключения папок не работают — плагин генерирует индексы по всему
   vault независимо от настроек (подтверждено чтением исходников: пустая строка в списке
   обнуляет фильтр, а запись `*` в списке исключений приводит к вызову `vault.delete`
   с несуществующим путём).
2. Имя индекс-файла в Waypoint жёстко равно имени папки, настраивается только префикс.

## Ключевое отличие от Zoottelkeeper
**MyMOC никогда не создаёт файлы.** Он только обновляет содержимое уже существующих
заметок, в которые пользователь сам вписал маркер. Отсюда следует, что списки
разрешённых и запрещённых папок не нужны в принципе: множество обрабатываемых файлов
задаётся наличием маркера, а не настройками. Засорить vault плагин не может физически.

## Поведение

### Маркер

Пользователь создаёт заметку с произвольным именем в нужной папке и вставляет строку:

```
%% MOC %%
```

При первой обработке плагин заменяет её на блок с ограничителями:

```
%% MOC:start %%
…список…
%% MOC:end %%
```

Далее обновляется только содержимое между ограничителями. Текст до и после блока —
заголовки, комментарии, ручные ссылки — не затрагивается.

Слово `MOC` настраивается. Регистр учитывается.

### Формат списка

```
🗂️ [[03_RESOURCES/SERVER/Terminal/Оглавление|Terminal]]
📄 [[03_RESOURCES/SERVER/API|API]]
🎨 [[03_RESOURCES/SERVER/Схема сети.canvas|Схема сети]]
```

Ссылки в формате `[[полный/путь/имя|отображаемое имя]]`. Для `.md` расширение в пути
опускается (соглашение Obsidian), для `.canvas` — сохраняется.

### Правила формирования

- Один уровень вложенности: содержимое родительской папки MOC-файла, вглубь не заходит
- Включаются `.md` и `.canvas`; вложения (изображения, PDF) — нет
- Порядок: сначала подпапки, затем файлы; внутри каждой группы — по алфавиту,
  сравнение через `localeCompare` (корректно для кириллицы)
- Сам MOC-файл в свой список не попадает
- Ссылка на подпапку ведёт на MOC-файл внутри неё, найденный по маркеру. Если такого
  файла нет, выводится строка со значком и именем папки без ссылки — Obsidian не умеет
  ссылаться на каталог. Если в подпапке несколько файлов с маркером, берётся первый
  по алфавиту (случай редкий, поведение должно быть предсказуемым, а не случайным)
- Если маркер встречается в файле несколько раз, обрабатывается только первый,
  остальные остаются как есть
- Если папка пуста, между ограничителями остаётся пустая строка

### Триггеры обновления

| Событие | Что обновляется |
|---|---|
| создание файла или папки | MOC родительской папки нового объекта |
| удаление файла или папки | MOC папки, где объект находился |
| переименование или перемещение | MOC папки-источника и папки-получателя |
| открытие файла | этот файл, если в нём есть маркер |
| команда «Обновить MOC» | активный файл |

Обновление при открытии нужно, чтобы блок разворачивался сразу после того, как
пользователь вписал маркер в существующую заметку.

### Защита от зацикливания

Плагин записывает файл только если собранный список отличается от текущего содержимого
блока. Иначе запись плагина вызвала бы событие изменения, которое привело бы к новой
записи.

Дополнительно: события создания файлов, приходящие во время начальной загрузки vault,
игнорируются (Obsidian выдаёт `create` на каждый файл при старте). Стандартный приём —
подписка внутри `app.workspace.onLayoutReady`.

## Настройки

Три параметра, больше не требуется:

| Параметр | По умолчанию |
|---|---|
| Слово маркера | `MOC` |
| Значки: файл / canvas / папка | `📄` / `🎨` / `🗂️` |
| Порядок сортировки | по алфавиту, А→Я |

Списков папок нет намеренно — см. «Ключевое отличие».

## Устройство

Два модуля с чёткой границей:

**`src/buildIndex.ts`** — чистая функция. Принимает описание содержимого папки
(массив имён с признаком «папка/файл/canvas» и путями), путь самого MOC-файла и
настройки. Возвращает массив строк. От Obsidian API не зависит вовсе, поэтому
тестируется обычным тестом без моков среды.

**`src/main.ts`** — обвязка: подписка на события vault, поиск блока в тексте,
чтение содержимого папки через Obsidian API, запись изменений, вкладка настроек.

Такое разделение выбрано потому, что вся содержательная логика (сортировка, фильтрация
по типам, формирование ссылок, обработка пустой папки) лежит в функции, которую можно
проверить за секунду, а часть, зависящая от среды, остаётся тонкой и проверяется вручную.

## Проверка

Один тестовый файл на `buildIndex` со случаями:

- смесь файлов, canvas и папок → правильный порядок и значки
- вложения (`.png`, `.pdf`) отброшены
- сам MOC-файл исключён из своего списка
- подпапка с MOC → ссылка; подпапка без MOC → строка без ссылки
- пустая папка → пустой список
- кириллица сортируется правильно (`Яблоко` после `Апельсин`, не наоборот)

Запуск через `node --test`, без фреймворков.

Обвязка проверяется вручную в живом vault: вписать маркер, создать файл рядом,
удалить его, переименовать, убедиться, что список меняется, а текст вокруг блока цел.

## Сборка и доставка

Сборка esbuild в один `main.js`. К пользователю попадают три файла — `main.js`,
`manifest.json`, `styles.css` (последний может быть пустым) — в каталог
`.obsidian\plugins\mymoc\` на Windows-машине. Папка `.obsidian` намеренно исключена
из синхронизации, поэтому доставка ручная: файлы передаются пользователю, он
кладёт их и включает плагин в списке. Тем же путём обновления.

## Что осознанно не делается

- Рекурсивное дерево — выбран один уровень, как в текущих MOC пользователя
- Frontmatter, теги, шаблоны Templater — у Zoottelkeeper это было, здесь не нужно
- Списки включённых/исключённых папок — заменены маркером
- Автосоздание MOC-файлов — источник основной проблемы, ради которой всё затевалось
- Сортировка по дате изменения — при необходимости добавится одним параметром
