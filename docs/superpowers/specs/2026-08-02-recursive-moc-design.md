# MyMOC: рекурсивное создание оглавлений — `%% +MOC %%`

Дата: 2026-08-02. Дополняет [дизайн v1](2026-08-01-mymoc-design.md).

## Задача

Одним действием завести оглавления во всей ветке папок, а не расставлять маркеры
руками в каждой подпапке.

## Поведение

Пользователь вписывает в заметку:

```
%% +MOC %%
```

Плагин обходит всю ветку под папкой этой заметки и в каждой подпапке создаёт файл
`-ИмяПапки.md`, содержащий готовый развёрнутый блок оглавления. Затем `%% +MOC %%`
в исходной заметке превращается в обычный блок — маркер срабатывает **однократно**.

Созданные файлы дальше живут как обычные оглавления: обновляются при добавлении,
удалении и переименовании файлов рядом.

### Правила создания

| Условие | Поведение |
|---|---|
| в подпапке уже есть файл с маркером | пропустить, ничего не создавать |
| файл `-ИмяПапки.md` уже существует | пропустить, **не перезаписывать** |
| подпапка пуста (нет заметок, canvas и подпапок) | пропустить |
| глубина | вся ветка, без ограничения |
| папка самой заметки | не затрагивается, там разворачивается блок |

Содержимое создаваемого файла — только блок:

```
%% MOC:start %%
📄 [[путь/Заметка|Заметка]]
%% MOC:end %%
```

Обычный маркер `MOC`, а не `+MOC`: рекурсия уже отработала за один проход,
повторять её на каждом уровне не нужно.

### Почему плюс спереди

Obsidian закрывает `%%` сразу при вводе, поэтому слово печатается внутри готовой пары.
С плюсом в конце набор проходил бы через состояние `%% MOC %%` — обычный маркер
срабатывал бы по дебаунсу и схлопывал строку в блок раньше, чем удастся дописать плюс.
С префиксом промежуточные состояния (`%% + %%`, `%% +M %%`) ни на что не похожи.

### Имя файла

`-` + имя папки + `.md`. Дефис не косметика: фильтры Syncthing отсекают `-*.md`,
поэтому созданные оглавления не уезжают внутрь git-репозиториев на сервере.
Префикс берётся из настроек (по умолчанию `-`), чтобы при смене соглашения
не пришлось править код.

### Итог работы

Уведомление Obsidian: сколько файлов создано и сколько подпапок пропущено.
Без него непонятно, отработала ли команда, особенно если пропущено всё.

## Почему это не повторяет Zoottelkeeper

Автосоздание файлов было причиной, по которой предшественник засорял vault.
Здесь оно ограничено тремя условиями:

1. Происходит по явному действию пользователя, а не в фоне
2. Срабатывает ровно один раз — маркер после прохода исчезает
3. Никогда не перезаписывает существующее

Формулировку в README придётся поправить: не «никогда не создаёт файлы»,
а «не создаёт файлы сам по себе».

## Устройство

**`src/buildIndex.ts`** — добавляются:

- `hasRecursiveMarker(content, marker)` — распознаёт `%% +MOC %%`, игнорируя код
- `planMocCreation(folders, prefix)` — чистая функция планирования: получает описание
  подпапок (путь, имя, есть ли содержимое, есть ли уже оглавление) и возвращает список
  файлов к созданию. Никакого ввода-вывода, поэтому проверяется обычными тестами
- `applyMocBlock` учится разворачивать и `%% +MOC %%`

**`src/main.ts`** — обвязка: рекурсивный обход дерева через Obsidian API, сбор описаний
для планировщика, создание файлов по возвращённому списку, уведомление.

Граница та же, что и в v1: решения принимает чистая функция, обвязка только читает
файловую систему и исполняет.

## Проверка

Тесты на `planMocCreation`:

- папка с заметками и без оглавления → попадает в план
- папка, где уже есть файл с маркером → пропущена
- папка, где уже есть файл с таким именем → пропущена
- пустая папка → пропущена
- папка, содержащая только подпапки → попадает в план
- вложенность в несколько уровней → все уровни в плане
- нестандартный префикс подставляется в имя

Тесты на `hasRecursiveMarker`: распознаётся `%% +MOC %%`, не распознаётся `%% MOC %%`,
не распознаётся маркер внутри кода.

Обвязка проверяется вручную: вписать `%% +MOC %%` в заметку над деревом папок,
убедиться, что оглавления появились на всех уровнях, существующие файлы целы,
а маркер превратился в блок.

## Что осознанно не делается

- Подтверждение перед созданием — действие обратимо, уведомление сообщает результат
- Откат созданного — файлы удаляются как обычные заметки
- Рекурсивное обновление по расписанию — созданные оглавления обновляются сами,
  каждое в своей папке
